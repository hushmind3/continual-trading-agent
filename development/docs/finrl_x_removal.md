# FinRL-X 제거·Expert 분류 결과

현재 상태 기준: 2026-10-14. 이전 분리·정리 보고서는 당시 작업 기록이며 설치·경로의 현재 기준은 이 문서와 각 구현 폴더 README입니다.

## 금융 백엔드

- 기존 price_data/와 provider_settings/ 폴더를 backend/stockrl/finrl/ 아래로 이동했습니다.
- 가격 저장·조회는 price_data/storage.py의 PriceStore, 정리는 clean_price_data가 담당합니다. 기존 중복 제거·가격/조정계수 검증·조정 가격 계산·upsert 규칙을 유지했습니다.
- 중앙 학습·운영·일부 주식 Expert 입력은 price_data/operations.py를 호출합니다. FinRL-X import·sys.path 추가는 없습니다.
- 공급원 인증 조회·저장은 기존 OS keyring과 환경변수를 사용합니다. 설정됨과 실제 원격 인증·시세 수신 성공은 별도로 구분합니다.
- FinRL/SB3의 공식 알고리즘·환경·기본값은 수정하지 않았습니다. 기존 Champion 파일의 format 문자열은 직렬화 식별자이며 FinRL-X 실행 의존성이 아닙니다.
- FinRL-X 원본 함수 수동 실행 등록·소스 목록·서브모듈 등록·설치·서버 소스 해시 연결을 제거했습니다. FinRL 원본 함수 도구는 유지합니다. FinRL-X의 미사용 전략·웹·브로커 도구를 새 기능으로 복제하지 않았습니다.
- FinRL-X 원본·연결 로더·전용 요구사항은 상대 경로를 유지해 휴지통으로 이동했습니다. 기존 휴지통 내용은 열람·수정하지 않았습니다.

## 데이터

사용자 지시에 따라 기존 DB 보존·복사를 전제로 하지 않습니다. 현재 저장소는 data/market_prices.sqlite3이며 새 저장소의 가격 행은 0개입니다. data/finrl_trading.db는 의존 경로를 전환한 뒤 휴지통으로 이동했습니다. runtime/의 기존 실시간 CSV·봉 저장소는 유지합니다. 실제 시세가 들어오면 새 가격 저장소에 적재합니다.

## Expert

기존 바탕화면 모델/experts 폴더와 market/·action/ 분류 폴더를 재사용합니다. 사용자 최종 지시대로 패키지를 해당 분류의 원본 모델 폴더에 넣었습니다. 파일명은 ORIGINAL.pt, FP16.pt, BF16.pt, INT8.pt, INT4.pt, NF4.pt이며 UUID·해시를 붙이지 않습니다.

- market/: 등록된 시장·시계열 Expert 패키지 43개.
- action/: 등록된 행동·정책 출력 Expert 패키지 22개.
- 추가 GGUF·JSON 자산은 market/에 함께 정리했습니다.
- configs/experts.json의 등록 참조를 새 위치로 갱신했습니다. 신규 등록·변환·GGUF 저장도 같은 분류를 사용합니다.
- expert-packages 중간 폴더를 만들지 않습니다. 기존 원본 다운로드 폴더는 각 분류 아래에 유지합니다.
- 모델 가중치를 삭제·재다운로드·재학습하지 않았습니다. 분류 초기 단계에서 등록 패키지 65개의 형식·참조 파일을 확인했습니다. 이후 사용자 지시로 PT 개별 읽기·Expert 기능 검사를 중단했습니다. 최종 파일명 이동은 등록 JSON만 사용했으며 PT 내용은 수정·검사하지 않았습니다.

## Streamlit

pyproject.toml의 직접 요구사항, 설치 명세와 operations.lock.txt의 Streamlit·Altair·Pydeck 항목을 제거했습니다. 프로젝트 설치 메타데이터도 갱신했습니다. 다른 활성 패키지의 의존성이 없는 것을 확인한 뒤 세 패키지의 설치 파일 676개를 휴지통으로 이동했습니다. 새 패키지 설치·버전 업그레이드는 하지 않았습니다. 세 모듈의 import 검색 결과는 모두 없음입니다.

## 실제 검증

- Python 회귀 테스트 32개 통과. 첫 실패는 자동 이어 학습 테스트의 잘못된 mock 참조였으며 수정 후 전체 통과했습니다.
- TypeScript 타입 검사와 Vite 프론트 빌드 통과.
- FinRL-X import를 강제로 차단한 새 Python 프로세스에서 API 모듈 초기화 성공.
- 로컬 서버 적용·API framework/menu_catalog 응답 확인. FinRL-X 소스 목록 0개, 제거한 소스 폴더·기존 DB는 작업 경로에 없습니다.
- 프론트 API 계약 테스트 4개 통과. 초기 브라우저 검사 2개 통과. 전체 화면 검사는 기존 테스트가 메뉴 11개를 고정 기대해 실패했으며, 실제 API 등록 목록과 비교하도록 수정한 뒤 최종 9개 화면 모두 통과했습니다. JavaScript 예외·HTTP 500은 없었습니다. Expert 기능·추론 검사는 수행하지 않았습니다.
- 실제 시세 수신·외부 공급원 인증·신규 정책 생성·학습·백테스트·가상/실제 주문·65개 Expert 전체 추론은 실행하지 않았습니다.

모듈·도구 별도 소메뉴와 프론트·백엔드 등록 폴더를 제거하고, 기능을 백엔드 기능 전체의 원본 모듈·함수 탭으로 통합했습니다. 구현 파일도 management/all_backend_features/ 아래로 옮겼습니다.

## 사용자 최종 PT 폐기 지시

사용자 지시에 따라 바탕화면 모델 폴더 아래 PT 파일 68개를 상대 경로를 유지해 프로젝트 휴지통/models/로 이동했습니다. 등록 PT 65개와 관련 활성 등록을 configs/experts.json에서 제거했습니다. 현재 등록 Expert는 0개입니다. 기존 role 분류·원본 폴더·INT4.pt 등 파일명 정리는 폐기 전 작업 기록이며 새 모델을 생성·다운로드·학습하지 않았습니다. 이후 PT 개별 읽기와 Expert 기능 검사는 실행하지 않습니다. JSON/GGUF 등 비-PT 자료는 해당 모델 폴더에 유지합니다.

메뉴 합치기 이후 타입 검사와 Vite 빌드는 통과했습니다. Python 32개 검사 결과는 PT 폐기 전 확인 결과이며, 새로 Expert 검사를 실행한 것으로 표시하지 않습니다.

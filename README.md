# FinRL-X MoE Operations

실시간 시장 데이터와 기존 `champion.pt` MoE를 연결하는 금융 운영 도구입니다. FinRL-X의 목표 비중 중심 구조를 기준으로 데이터·전략·위험검사·가상계좌를 연결하고, TorchRL PPO가 실제 시장 결과로 의사결정부를 학습합니다.

## 동작

`실시간 시세 → 사용 가능한 frozen Expert 출력 → 학습된 MoE 결합부 / 64D latent → 시장·계좌 feature → TorchRL Allocator → target weights → 잔고·가격 유효성 확인 → FinRL-X StrategyResult → 가상체결 → 비용 반영 손익 → 지속학습`

- Expert 원본 가중치는 frozen입니다. `champion.pt`의 실제 Adapter·Router·Fusion·Attention·Controller를 복원하며, 새 랜덤 정책으로 대체하지 않습니다.
- 종목 비중·현금 비중·비중 변경·손실 대응은 모델이 결정합니다. 고정 비중·turnover 제한이나 MDD 강제 청산 규칙을 적용하지 않습니다. 현금 계좌의 잔고, 체결 비용과 실제 가격은 그대로 계산합니다.
- `champion.pt`는 선택된 양자화 Expert 가중치와 중앙 학습 상태를 포함하는 통합 MoE입니다. 실행 버튼 하나로 같은 GPU 소유 프로세스의 Expert·중앙 판단·TorchRL PPO를 복원합니다. 판단과 학습은 독립 작업 스레드이며, 판단은 마지막 발행 가중치를 사용합니다. 시세 수집은 별도로 실행합니다. GGUF는 Champion 내부 바이트를 전용 llama.cpp 엔진 파일로 적재합니다.
- 중앙 판단과 PPO는 CUDA가 있으면 GPU에서 실행합니다. Expert도 시작 시 GPU에 먼저 적재하며 VRAM 초과분만 RAM/부분 레이어 오프로드를 사용합니다. Expert 출력은 같은 프로세스의 메모리 캐시로 전달하고, 텐서 출력을 지원하는 실행기는 GPU 텐서를 그대로 결합부에 연결합니다. 원본 API가 NumPy·DataFrame·JSON을 반환하면 그 작은 출력만 GPU 입력으로 옮깁니다. 전용 llama.cpp 엔진도 같은 MoE가 소유·관리합니다.
- 학습한 결합부·Allocator·optimizer 상태는 작은 정책 버전으로 즉시 저장하고 운영 판단에 반영합니다. 정상 정지·구성 변경 때 최신 중앙 상태를 전체 Champion에 합칩니다. 고정된 대용량 Expert 전체를 매 학습마다 다시 쓰지 않습니다. 실행 중 장애가 나도 정상 체크포인트에서 복원합니다.
- 가상체결은 다음 완료 시세에서 처리하며, 수수료·가격 미끄러짐·계좌 비용을 포함합니다. 원화와 달러 계좌는 별도로 계산합니다. 실제 주문은 연결하지 않습니다.
- 한국 주식은 KRW, 미국 주식은 USD의 독립 계좌입니다. 모델의 계좌 입력과 reward도 해당 통화의 잔고·손익을 사용합니다. 환전·금액 합산은 하지 않습니다.
- 체결은 계좌 상태와 함께 SQLite 원장에 통화별로 저장하며 페이지로 조회합니다. 누적 체결 횟수와 조회 가능한 원장 건수를 구분하고, 과거 기록이 없는 경우 누락을 표시합니다.
- Allocator는 학습된 점수에서 비중이 정확히 0인 종목도 선택할 수 있습니다. PPO는 실제 체결 비중으로 변환된 같은 잠재 행동의 likelihood와 reward를 학습하며, 보유 종목 수를 고정하지 않습니다. 정수 주식 수량으로 반올림했을 때 변화가 없는 목표에는 주문을 생성하지 않습니다.
- 경험 처리와 계좌·미체결 상태는 SQLite transaction으로 함께 저장합니다. 정책 checksum, 버전 복원, 프로세스 식별과 재시도로 재시작을 지원합니다.
- 현재 MoE에는 시장 분석 Expert 7개와 주식 매매 판단 Expert 5개, 총 12개가 포함됩니다. 실제 실행은 선택한 Expert의 입력·RAM·VRAM 조건에 따라 달라지며, 자원이 부족하면 실행을 보류하고 화면에 자원 대기로 표시합니다.
- 운영의 고정 가중치는 `champion.pt` 내부에서 읽습니다. 라이브러리 패키지는 검사·교체·재추가용 부품이며 실행 시 각 패키지를 다시 읽지 않습니다. Expert 제외 시 통합 파일에서 해당 몸체가 빠지고 전체 frozen 파라미터·파일 크기가 감소합니다. 중앙 모델과 전체 Expert의 파라미터 수·가중치 크기는 화면에서 구분합니다. 학습은 파라미터 값을 갱신하며, 중앙 네트워크 자체의 자동 용량 확장은 구현되어 있지 않습니다.

## Expert 슬롯 관리

MoE 화면에서 파일 구성 확인 뒤 가져오거나 검색 결과를 다운로드하면 양자화·실제 실행 검사·운영 구성 추가를 자동으로 진행합니다. 실패하면 추가를 차단하고 이유를 표시합니다. Frozen Expert 패키지 또는 호환 MoE `.pt` 파일의 로컬 경로·다운로드 주소를 사용할 수 있습니다.

- 원본 입력 생성기가 없거나 실제 데이터·출력 규격·자원 검사를 통과하지 못한 모델은 사용 구성에 넣지 않습니다. 가중치만 있는 파일의 구조와 입력을 추측하지 않습니다.
- 지원하는 입력 계열의 새 패키지는 출력 크기에 맞춰 Adapter·Router 연결을 자동으로 생성합니다. 기존 슬롯과 공통 의사결정부의 학습 가중치·Adam 상태는 이어받습니다.
- 슬롯 사용·교체·제외는 정상 정지·최신 학습 저장·통합 Champion 재구성·기존 실행 제어 복원 순서로 처리합니다. 제외된 슬롯의 학습 연결과 Adam 상태는 보존하고 몸체·고정 모델 메모리는 제거합니다. 부품 라이브러리에는 남으므로 버튼으로 다시 추가할 수 있습니다.
- 실제 삭제는 가중치 패키지와 해당 학습 연결을 제거하고 저장된 정책들을 자동으로 맞춥니다. 다시 사용할 모델은 삭제 대신 제외하세요.
- 기존 경험에는 당시의 Expert 사용 마스크를 저장합니다. 슬롯 선택 체크포인트와 실제 학습 세대를 분리하여 선택 변경만으로 학습 경험이 만료되지 않게 합니다. 시장 Expert를 추가할 때는 새 슬롯을 당시 이용 불가로 표시해 호환 경험·미체결 상태를 이어받습니다. 삭제·출력 변경처럼 기존 관측을 그대로 사용할 수 없는 구성에서는 호환되지 않는 미처리 경험을 제외합니다.
- Expert의 실행기·입출력 계약·정밀도는 교체 가능한 부품 특성입니다. FP32·FP16·INT4 같은 정밀도는 파일 확장자와 별개이며, 현재 지원하지 않는 실행 방식은 실제 검사에서 제외합니다.
- 같은 구조와 입력 규칙의 원본 PT/PTH/Safetensors 또는 SB3 ZIP 가중치는 검증된 템플릿으로 새 슬롯에 가져올 수 있습니다. 입력 규칙이 달라지는 모델은 해당 원본 정의를 포함한 패키지가 필요합니다.
- 출력·속도·메모리 비교는 같은 실제 입력을 고정하고 별도 프로세스에서 반복 측정합니다. 평균·최대 출력 오차, 상대 RMSE, 판단 일치, 초기 적재·반복 추론 시간, peak RAM/VRAM, 파일 크기를 비교합니다. 매매 수익률 검증과 구분하며 계좌와 학습 상태를 변경하지 않습니다.
- 새 버전은 새 슬롯으로 검사한 뒤 전환합니다. 정책 버전 복원 시 해당 버전의 사용 슬롯도 함께 복원합니다.
- **등록 모델 실행 검사**는 보관한 원본·변환 버전 모두를 자동으로 순차 검사합니다. 입력·파일 무결성·출력 크기·추론 3회·RAM/VRAM을 확인하고, 변환 버전은 동일 입력과 난수 시드로 원본 대비 출력 차이도 검사합니다. 실패한 항목은 이유를 남기고 다음 모델을 계속 검사하며 사용 슬롯을 자동 변경하지 않습니다.
- **금융 Expert 자동 검색**은 FinText·FinRL·finance·financial·MarketGPT와 시장 예측에 활용 가능한 Chronos·TimesFM·Kronos·FinCast·Time-MoE의 인기 모델과 최근 업데이트 모델을 함께 조회합니다. 결과에 실제 가중치 파일 크기, 저장소 등록일·수정일, 설치된 revision, 입력 역할 중복, 검증한 입력/API 요구사항과 원본 문서 단서를 표시합니다. 원본에 명시된 릴리즈 날짜가 없으면 미기재로 표시하며 등록일·수정일을 릴리즈 날짜로 간주하지 않습니다. 호환 후보의 **다운로드·검사·자동 사용**를 누르면 모델 폴더에 불변 패키지를 생성하고 실제 추론과 기존 템플릿 대비 측정을 자동 실행합니다. 입력·실행기를 확인할 수 없는 모델은 구성에 넣지 않습니다. 검색 호환성은 투자성과 평가와 별개입니다.
- 추론 시간은 진단으로만 표시합니다. 서로 다른 실행 장치의 속도 배수는 계산하지 않으며, CPU 또는 FP32보다 빨라야 한다는 선택 조건을 적용하지 않습니다.
- 설치된 공식 Chronos-2/Bolt 실행 API를 사용해 크기·구조가 다른 지원 모델도 새 슬롯으로 가져올 수 있습니다. 원격 Python 코드를 실행하거나 Expert를 재학습하지 않습니다. 같은 원본 revision은 중복 다운로드하지 않습니다.
- 동일 Expert의 원본·변환 버전과 실패 사유는 한 행에 모아 확인합니다. 자동 선택은 정상 실행되는 NF4/INT4/INT8 등 저비트 버전을 우선하고 VRAM 상주 크기를 기준으로 판단합니다. 원본 근사 오차나 추론 속도로 운영을 차단하지 않습니다. 새로 만든 미선택 파일은 휴지통으로 정리하고 비교 사유·측정 요약은 유지합니다.
- 원본·FP16·BF16·INT8·INT4의 상태를 같은 행에서 확인합니다. 현재 파일의 전체 검사 결과와 마지막 자동 최적화 판단을 구분하고, 미생성·변환 실패·정확도 탈락·성능 탈락·통과했지만 미선택된 경우도 사유를 표시합니다. 원본이 이미 해당 정밀도이면 별도 변환 불필요로 표시합니다. **판단 근거**에서 당시의 입력·목표 점수·추론 시간·peak RAM/VRAM·오차와 선택 이유를 확인하며, 정리된 후보는 측정 요약만 보존하고 사용할 수 없는 파일을 선택 대상으로 만들지 않습니다. 전체 검사 요약에는 통과한 항목을 포함한 모든 결과를 표시합니다.
- **변환** 버튼은 FP16/BF16 또는 Linear 가중치의 INT8/INT4 후보 생성, 실제 추론 검사, 동일 입력 3회 비교를 자동 실행합니다. 원본을 덮어쓰지 않으며 **원본과 교체**를 누르면 해당 Expert의 학습 연결과 optimizer 상태를 이어받습니다. 기본 적용 기준은 실제 입력·출력 형식·유한값·frozen 가중치 기능 검사를 통과하는 것입니다. 원본 출력의 상대 RMSE·판단 일치율은 진단으로 기록하며, 원본 근사 제한을 따로 켠 경우에만 지정 기준 초과를 차단합니다. 중앙 모델은 변환된 Expert 출력으로 계속 학습합니다. INT8/INT4는 일반 untied Linear의 압축 저장·상주를 지원하며 임베딩·공유 가중치·기타 계층은 원래 정밀도를 유지합니다. 계산 시 구간별로 복원하므로 전용 정수 연산 커널의 가속을 뜻하지 않으며, 속도·메모리 효과는 비교 결과로 판단합니다.

운영·학습·진단 화면은 가상체결 정지, 시세 정지, 첫 손익 확정 대기, 배치 부족, 가중치 업데이트를 같은 기준으로 표시합니다. 기본 목표 배치는 32개이며 같은 종목 구성의 확정 경험이 5분간 수집되면 최소 4개부터 작은 배치로 학습합니다. 결과가 확정되지 않은 경험이나 서로 다른 종목 구성은 섞지 않습니다. 수집 수·시간·최근 학습 경험과 누적 업데이트를 표시하며 최소 배치와 수집 시간은 연결 화면의 학습 설정에서 조절합니다.

변환·검사·측정은 기본적으로 RAM/VRAM 여유와 측정된 peak 사용량에 따라 CUDA를 활용합니다. 변환은 구간별 CUDA 연산 후 CPU 저장을 사용하고, 추론에 필요한 VRAM이 부족하면 자동 모드는 CPU를 선택합니다. 장치 지정과 실제 선택 이유를 표시하며 자동 비교에서 서로 다른 장치를 사용했으면 결과에 명시합니다. 관찰 종목 수는 고정하지 않습니다. 시장 예측 Expert는 실제 시계열을 확보한 종목에 적용하며, 원래 학습 종목·관측 차원이 고정된 주식 정책의 적용 범위는 Expert별로 표시합니다.

## GPU 상주 · 저비트 실행

- **사용 중 Expert 자동 양자화**은 사용 중인 Expert 전체를 NF4 → INT4 → INT8 후보로 변환·검사하고 메모리 중심으로 선택합니다. 양자화 불가능한 Expert는 운영에서 제외하도록 표시합니다. 학습한 중앙 의사결정부·기존 연결부·optimizer 상태는 이어받고, 새 슬롯이 없었던 과거 경험에는 해당 슬롯을 이용 불가로 기록합니다.
- bitsandbytes NF4는 압축 가중치를 전용 CUDA 커널로 실행합니다. 구조가 맞지 않으면 기존 packed INT4/INT8 실행기를 검사하며, 지원하지 않는 모델을 성공으로 처리하지 않습니다. Expert 가중치는 계속 frozen입니다.
- GGUF는 llama.cpp의 공식 Windows GPU 실행기를 사용합니다. GPU의 압축 커널과 RAM 혼합 적재를 사용하며, 이 PC에서는 작은 배포 파일과 NVIDIA 호환성을 위해 Vulkan 빌드를 사용합니다. PyTorch Expert는 CUDA로 실행합니다. 엔진과 실제 GPU 레이어·VRAM 사용량을 구분해서 표시합니다.
- GGUF 엔진의 시장별 프롬프트 RAM 캐시는 기본 비활성화합니다. 입력이 계속 바뀌는 운영에서 기본 8GiB 캐시가 누적되지 않도록 하며, 필요한 경우 `resources.gguf_prompt_cache_mib`로 작은 예산을 지정합니다.
- GGUF 원본이 FP32/FP16/BF16이면 공식 llama.cpp quantizer로 Q4_K_M을 생성합니다. 양자화 가중치 파일은 그대로 보관하고 작은 JSON 실행/입력 manifest로 연결하므로 큰 PT 파일에 다시 넣지 않습니다. 로컬 GGUF의 선언된 계약은 완료 가격 시계열에서 방향·확신·위험을 구조화해 출력하는 의견 모델이며, 주가 관측값 자체와 구분합니다.
- 지원하는 PyTorch 원본과 GGUF는 파일 확장자 자체로 실행 여부를 판단하지 않습니다. 해당 모델의 구조·입력 계약·추론 엔진을 확인하고 실제 실행을 검사합니다. 새 다운로드/가져오기는 양자화 검사까지 자동으로 진행합니다.
- GPU 캐시는 모델별 상주 가중치와 추가 연산 메모리를 구분해 예산을 잡습니다. 다른 상주 모델의 메모리를 현재 Expert의 workspace로 오인하지 않습니다. CPU/GPU 실행 시간 배수와 FP32 대비 속도는 자동 선택 기준에서 제외합니다.
- 검색은 Hugging Face와 GitHub의 최근 공개/업데이트 모델을 함께 조회하며 기본 범위는 최근 1년입니다. 3개월·6개월 또는 전체 검색으로 바꿀 수 있습니다. 저장소 수정 날짜를 모델 릴리즈 날짜로 간주하지 않습니다.

## 화면에서 실제 진행 확인

- 서비스 켜짐은 프로세스 생존 상태입니다. 운영·MoE·진단 화면은 최근 60초 동안 실제로 증가한 새 저장 봉, 분석 완료, 새 입력 분석, 중앙 판단, 학습 가중치 조정 수를 따로 표시합니다. 관찰 기간·프로세스 재시작도 표시하고 계측되지 않은 값을 0이나 진행 중으로 만들지 않습니다.
- 마지막 처리 완료 시각은 작업이 끝난 시간이고 사용 데이터 시각은 입력 관측 시간입니다. 같은 입력 재분석과 새 입력 처리를 구분합니다. 저장 버전 증가를 학습 조정 증가로 세지 않습니다.
- 마지막 학습 결과의 loss는 학습 계산값이며 계좌 손실이나 수익률이 아닙니다. 조회 가능한 측정값이 없어도 누적 조정·학습 완료 기록을 별도로 보여주므로 학습한 적이 없는 것으로 해석하지 않습니다.
- MoE 화면의 설명 패널에서 버튼의 부작용과 상태 의미를 펼쳐 볼 수 있습니다. 목록은 등록된 계약 기준으로 시계열 예측·매매 판단·시장 해석을 분류하며 GGUF 같은 확장자로 역할을 추정하지 않습니다.

## 실행

Windows에서는 Python 3.13, Node.js LTS, NVIDIA GPU에 맞는 드라이버를 준비한 뒤 `설치.cmd`를 실행합니다. 모델 파일은 바탕화면 `모델/champion.pt`를 사용하며 GitHub에 포함되지 않습니다.

`서버켜기.cmd`는 기본 프로젝트에서 Python API와 Vite를 함께 시작합니다.

- 운영 UI / API: <http://127.0.0.1:8766>
- 개발 UI: <http://127.0.0.1:5173>

시세·MoE·가상체결·자동학습은 화면에서 제어합니다. 키움 App Key와 Secret은 연결 화면에서 확인하며 운영체제 보안 저장소를 사용합니다. 국내 체결가와 미국 FE 시세는 공식 키움 SDK를 통해 수신합니다.

실행 여부, 시세 연결, 정책 버전, 학습 횟수와 계좌 수치는 운영 화면과 `/api/state`에서 확인합니다. 이 문서는 구조와 사용 방법을 설명하며 실시간 상태 수치를 보관하지 않습니다.

## 설정과 저장

- 운영 설정: `configs/operations.json`
- 원본 모델: `Desktop/모델/champion.pt`
- 고정 Expert 패키지: `Desktop/모델/expert-packages`
- 계좌·경험·시세·프로세스 상태: `runtime/finrlx`
- 정책·optimizer 버전: `runtime/finrlx/policies`
- React / Tailwind CSS / Vite: `frontend`
- 운영 API·Expert 서비스·TorchRL 학습: `src/stockrl/platform`

`runtime`, `.venv`, `node_modules`, 키움 로컬 설정과 가중치는 Git에서 제외합니다. 정상 정지한 `champion.pt`에는 선택된 Expert와 최신 중앙 학습 상태가 들어 있어 현재 MoE를 복원할 수 있습니다. 다른 PC에서 계좌·경험·시세까지 이어 운영하려면 `runtime/finrlx`도 옮깁니다. 미사용 부품을 다시 추가·검사하려면 모델 폴더의 라이브러리도 함께 옮깁니다.

## 개발 확인

```powershell
$env:PYTHONPATH="src"
$env:PYTHONUTF8="1"
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
cd frontend
npm run typecheck
npm test
npm run build
```

브라우저 테스트는 실행 중인 8766 서버와 설치된 Microsoft Edge를 사용합니다. 빌드 결과 `frontend/dist`를 Python 서버가 직접 제공하며 `no-store`로 응답합니다.

상세 구조는 [운영 architecture](docs/architecture.md), 설치는 [Windows 설치](docs/windows-install.md), 저장 위치는 [저장 안내](docs/project-storage.md)를 참고하세요.

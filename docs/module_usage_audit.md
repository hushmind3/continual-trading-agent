# 모듈 사용 구분·정리 결과

## 화면 분류

| 사용 구분 | 정확한 의미 |
| --- | --- |
| 운영 코드 참조 | 서버·CLI·작업 진입점에서 이어지는 import 관계가 있음. 실제 함수 실행 성공과는 별도 |
| 수동 실행 전용 | 운영 코드 참조는 없으며 모듈·도구에서 사용자가 원본 함수를 선택하는 실행 경로가 있음 |
| 참조 경로 없음 | 운영 import·수동 실행 등록이 확인되지 않음. 설치·검사·동적 import도 확인한 뒤 삭제 판단 |
| 소스 해석 실패 | 소스를 읽거나 해석하지 못해 사용 여부를 판단할 수 없음 |

import는 현재 서버 적재와 import 실패 기록을 표시합니다. 함수 실행은 성공 기록·최근 실패·기록 없음으로 표시하며, 일부 함수 성공을 모듈 전체 정상 작동으로 표시하지 않습니다.

인증은 소스에서 탐지한 인증 입력 이름을 보여 줍니다. 공급원 이름만 보고 인증 필요·완료로 판단하지 않습니다. 입력 이름 미탐지는 인증이 필요 없다는 뜻이 아니며, 실제 인증 성공은 이번 작업에서 검사하지 않았습니다.

## 프로젝트 자체 모듈 의존성 조사

- 분석한 Python 소스: 110개. 프로젝트 코드를 import하거나 실행하지 않고 AST·import·명시적 프로세스 진입점 문자열을 확인했습니다.
- 운영 진입점에서 참조되는 백엔드 소스: 105개.
- 검사 스크립트에서만 참조되는 백엔드 소스: 0개.
- 운영·설치·검사 경로 어디에서도 참조되지 않는 구현 파일 후보: 0개.
- 해석 실패: 0개. 런타임 모듈 선택을 사용하는 동적 import 2곳은 추가 검토 항목으로 기록했습니다. 참조 후보가 없어 이를 근거로 파일을 삭제하지 않았습니다.
- 실제 폐기한 모듈: 0개. 설치된 공식 라이브러리의 수동 실행 경로를 미사용으로 오인해 삭제하지 않았습니다.

전체 경로와 조사 근거는 [module_usage_audit.json](module_usage_audit.json)에 있습니다. 공식 FinRL·FinRL-X 라이브러리는 프로젝트 자체 코드의 미사용 조사와 구분합니다.

## 사용자가 다시 조사할 명령

프로젝트 루트에서 `.venv\Scripts\python.exe -B scripts\audit_module_usage.py`를 실행합니다. 이 스크립트는 참조 조사 결과만 출력하며 파일 삭제·인증 검사·학습·추론·함수 실행을 하지 않습니다.

브라우저·타입·함수 실행·외부 인증 검사는 미실행입니다.

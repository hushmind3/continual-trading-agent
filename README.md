# FinRL-X MoE Operations

실시간 시장 데이터와 기존 `champion.pt` MoE를 연결하는 금융 운영 도구입니다. FinRL-X의 목표 비중 중심 구조를 기준으로 데이터·전략·위험검사·가상계좌를 연결하고, TorchRL PPO가 실제 시장 결과로 의사결정부를 학습합니다.

## 동작

`실시간 시세 → 사용 가능한 frozen Expert 출력 → 학습된 MoE 결합부 / 64D latent → 시장·계좌 feature → TorchRL Allocator → target weights → 잔고·가격 유효성 확인 → FinRL-X StrategyResult → 가상체결 → 비용 반영 손익 → 지속학습`

- Expert 원본 가중치는 frozen입니다. `champion.pt`의 실제 Adapter·Router·Fusion·Attention·Controller를 복원하며, 새 랜덤 정책으로 대체하지 않습니다.
- 종목 비중·현금 비중·비중 변경·손실 대응은 모델이 결정합니다. 고정 비중·turnover 제한이나 MDD 강제 청산 규칙을 적용하지 않습니다. 현금 계좌의 잔고, 체결 비용과 실제 가격은 그대로 계산합니다.
- Expert 실행, MoE 판단·계좌, CPU 학습은 별도 프로세스입니다. 큰 Expert는 순차적인 단기 작업 프로세스에서 실행하며 완료 후 모델 매핑과 임시 메모리를 해제합니다. 작은 정책은 CPU에서, 큰 예측모델은 설정과 측정된 자원에 맞는 장치에서 실행합니다.
- 큰 원본 PT를 매번 다시 쓰지 않고, 학습한 결합부·Allocator·optimizer 상태를 작은 정책 버전으로 저장합니다. 운영 판단에는 발행된 최신 버전이 반영됩니다.
- 가상체결은 다음 완료 시세에서 처리하며, 수수료·가격 미끄러짐·계좌 비용을 포함합니다. 원화와 달러 계좌는 별도로 계산합니다. 실제 주문은 연결하지 않습니다.
- 한국 주식은 KRW, 미국 주식은 USD의 독립 계좌입니다. 모델의 계좌 입력과 reward도 해당 통화의 잔고·손익을 사용합니다. 환전·금액 합산은 하지 않습니다.
- 체결은 계좌 상태와 함께 SQLite 원장에 통화별로 저장하며 페이지로 조회합니다. 누적 체결 횟수와 조회 가능한 원장 건수를 구분하고, 과거 기록이 없는 경우 누락을 표시합니다.
- Allocator는 학습된 점수에서 비중이 정확히 0인 종목도 선택할 수 있습니다. PPO는 실제 체결 비중으로 변환된 같은 잠재 행동의 likelihood와 reward를 학습하며, 보유 종목 수를 고정하지 않습니다. 정수 주식 수량으로 반올림했을 때 변화가 없는 목표에는 주문을 생성하지 않습니다.
- 경험 처리와 계좌·미체결 상태는 SQLite transaction으로 함께 저장합니다. 정책 checksum, 버전 복원, 프로세스 식별과 재시도로 재시작을 지원합니다.
- 현재 MoE에는 시장 분석 Expert 7개와 주식 매매 판단 Expert 5개, 총 12개가 포함됩니다. 실제 실행은 선택한 Expert의 입력·RAM·VRAM 조건에 따라 달라지며, 자원이 부족하면 실행을 보류하고 화면에 자원 대기로 표시합니다.
- 고정 가중치는 모델 폴더의 불변 Expert 패키지에서 읽습니다. `champion.pt`에는 패키지 참조와 최신 학습 상태를 저장합니다. 결합부·Allocator·optimizer·슬롯 선택은 작은 정책 체크포인트로 버전을 남기며 Champion에도 함께 반영합니다. 등록되지 않은 가중치 파일 읽기는 차단합니다.

## Expert 슬롯 관리

MoE 화면에서 **파일 구성 확인 → 가져오기·실제 추론 검사 → 사용** 순서로 추가합니다. Frozen Expert 패키지 또는 호환 MoE `.pt` 파일의 로컬 경로·다운로드 주소를 사용할 수 있습니다.

- 원본 입력 생성기가 없거나 실제 데이터·출력 규격·자원 검사를 통과하지 못한 모델은 사용 구성에 넣지 않습니다. 가중치만 있는 파일의 구조와 입력을 추측하지 않습니다.
- 지원하는 입력 계열의 새 패키지는 출력 크기에 맞춰 Adapter·Router 연결을 자동으로 생성합니다. 기존 슬롯과 공통 의사결정부의 학습 가중치·Adam 상태는 이어받습니다.
- 기존 슬롯의 사용·제외는 추론을 재시작하거나 고정 가중치를 다시 쓰지 않고 처리합니다. 선택 변경을 작은 체크포인트에 자동 저장합니다. 제외된 슬롯의 학습 연결은 보존하고 고정 모델 메모리는 해제합니다.
- 실제 삭제는 가중치 패키지와 해당 학습 연결을 제거하고 저장된 정책들을 자동으로 맞춥니다. 다시 사용할 모델은 삭제 대신 제외하세요.
- 기존 경험에는 당시의 Expert 사용 마스크를 저장합니다. 슬롯 선택 체크포인트와 실제 학습 세대를 분리하여 선택 변경만으로 학습 경험이 만료되지 않게 합니다. 시장 Expert를 추가할 때는 새 슬롯을 당시 이용 불가로 표시해 호환 경험·미체결 상태를 이어받습니다. 삭제·출력 변경처럼 기존 관측을 그대로 사용할 수 없는 구성에서는 호환되지 않는 미처리 경험을 제외합니다.
- Expert의 실행기·입출력 계약·정밀도는 교체 가능한 부품 특성입니다. FP32·FP16·INT4 같은 정밀도는 파일 확장자와 별개이며, 현재 지원하지 않는 실행 방식은 실제 검사에서 제외합니다.
- 같은 구조와 입력 규칙의 원본 PT/PTH/Safetensors 또는 SB3 ZIP 가중치는 검증된 템플릿으로 새 슬롯에 가져올 수 있습니다. 입력 규칙이 달라지는 모델은 해당 원본 정의를 포함한 패키지가 필요합니다.
- 출력·속도·메모리 비교는 같은 실제 입력을 고정하고 별도 프로세스에서 반복 측정합니다. 평균·최대 출력 오차, 상대 RMSE, 판단 일치, 초기 적재·반복 추론 시간, peak RAM/VRAM, 파일 크기를 비교합니다. 매매 수익률 검증과 구분하며 계좌와 학습 상태를 변경하지 않습니다.
- 새 버전은 새 슬롯으로 검사한 뒤 전환합니다. 정책 버전 복원 시 해당 버전의 사용 슬롯도 함께 복원합니다.
- **전체 검사**는 보관한 원본·변환 버전 모두를 자동으로 순차 검사합니다. 입력·파일 무결성·출력 크기·추론 3회·RAM/VRAM을 확인하고, 변환 버전은 동일 입력과 난수 시드로 원본 대비 출력 차이도 검사합니다. 실패한 항목은 이유를 남기고 다음 모델을 계속 검사하며 사용 슬롯을 자동 변경하지 않습니다.
- **금융 Expert 자동 검색**은 FinText·FinRL·finance·financial·MarketGPT와 시장 예측에 활용 가능한 Chronos·TimesFM·Kronos·FinCast·Time-MoE의 인기 모델과 최근 업데이트 모델을 함께 조회합니다. 결과에 실제 가중치 파일 크기, 저장소 등록일·수정일, 설치된 revision, 입력 역할 중복, 검증한 입력/API 요구사항과 원본 문서 단서를 표시합니다. 원본에 명시된 릴리즈 날짜가 없으면 미기재로 표시하며 등록일·수정일을 릴리즈 날짜로 간주하지 않습니다. 호환 후보의 **다운로드·자동 검사**를 누르면 모델 폴더에 불변 패키지를 생성하고 실제 추론과 기존 템플릿 대비 측정을 자동 실행합니다. 입력·실행기를 확인할 수 없는 모델은 구성에 넣지 않습니다. 검색 호환성은 투자성과 평가와 별개입니다.
- 속도 비교는 배수 대신 **추론 시간 증가·감소율**을 표시합니다. 내부 비율은 `기준 추론 시간 / 비교 대상 추론 시간`이므로 0.83이면 대상의 추론 시간이 약 20.5% 더 길고, 1.29이면 약 22.5% 더 짧습니다. 실행 장치가 다르면 그 차이를 함께 표시합니다.
- 설치된 공식 Chronos-2/Bolt 실행 API를 사용해 크기·구조가 다른 지원 모델도 새 슬롯으로 가져올 수 있습니다. 원격 Python 코드를 실행하거나 Expert를 재학습하지 않습니다. 같은 원본 revision은 중복 다운로드하지 않습니다.
- 동일 Expert의 원본·변환 버전은 한 행에 모아 크기·오차·속도·사용 상태를 비교합니다. **자동 최적화**는 실제 입력을 한 번 고정하고 FP16/BF16/INT8/INT4를 생성 또는 재사용하여 검사·측정합니다. 정확도 기준을 통과한 버전 중 속도·메모리 목표에 맞고 5% 이상 개선된 버전을 선택해 현재 사용 중인 부품을 자동 교체하며 학습 상태를 이어받습니다. 균형 목표는 지연 60% / 시스템 대비 peak RAM·VRAM 압력 40%를 사용합니다. 최적화 중 새로 만든 미선택 파일은 휴지통으로 보내고, 원본과 사용자가 이미 보관한 버전은 유지합니다.
- **변환** 버튼은 FP16/BF16 또는 Linear 가중치의 INT8/INT4 후보 생성, 실제 추론 검사, 동일 입력 3회 비교를 자동 실행합니다. 원본을 덮어쓰지 않으며 **원본과 교체**를 누르면 해당 Expert의 학습 연결과 optimizer 상태를 이어받습니다. 기본 적용 기준은 상대 RMSE 1% 이하와 판단 일치 99% 이상이며 변환·비교 화면에서 조절합니다. 기준을 넘으면 교체를 차단합니다. INT8/INT4는 일반 untied Linear의 압축 저장·상주를 지원하며 임베딩·공유 가중치·기타 계층은 원래 정밀도를 유지합니다. 계산 시 구간별로 복원하므로 전용 정수 연산 커널의 가속을 뜻하지 않으며, 속도·메모리 효과는 비교 결과로 판단합니다.

운영·학습·진단 화면은 가상체결 정지, 시세 정지, 첫 손익 확정 대기, 배치 부족, 가중치 업데이트를 같은 기준으로 표시합니다. 기본 목표 배치는 32개이며 같은 종목 구성의 확정 경험이 5분간 수집되면 최소 4개부터 작은 배치로 학습합니다. 결과가 확정되지 않은 경험이나 서로 다른 종목 구성은 섞지 않습니다. 수집 수·시간·최근 학습 경험과 누적 업데이트를 표시하며 최소 배치와 수집 시간은 연결 화면의 학습 설정에서 조절합니다.

변환·검사·측정은 기본적으로 RAM/VRAM 여유와 측정된 peak 사용량에 따라 CUDA를 활용합니다. 변환은 구간별 CUDA 연산 후 CPU 저장을 사용하고, 추론에 필요한 VRAM이 부족하면 자동 모드는 CPU를 선택합니다. 장치 지정과 실제 선택 이유를 표시하며 자동 비교에서 서로 다른 장치를 사용했으면 결과에 명시합니다. 관찰 종목 수는 고정하지 않습니다. 시장 예측 Expert는 실제 시계열을 확보한 종목에 적용하며, 원래 학습 종목·관측 차원이 고정된 주식 정책의 적용 범위는 Expert별로 표시합니다.

## 실행

Windows에서는 Python 3.13, Node.js LTS, NVIDIA GPU에 맞는 드라이버를 준비한 뒤 `설치.cmd`를 실행합니다. 모델 파일은 바탕화면 `모델/champion.pt`를 사용하며 GitHub에 포함되지 않습니다.

`서버켜기.cmd`는 기본 프로젝트에서 Python API와 Vite를 함께 시작합니다.

- 운영 UI / API: <http://127.0.0.1:8766>
- 개발 UI: <http://127.0.0.1:5173>

시세·MoE·가상체결·자동학습은 화면에서 제어합니다. 키움 App Key와 Secret은 연결 화면에서 확인하며 운영체제 보안 저장소를 사용합니다. 국내 체결가와 미국 FE 시세는 공식 키움 SDK를 통해 수신합니다.

실행 여부, 시세 연결, 정책 버전, 학습 횟수와 계좌 수치는 운영 화면과 `/api/state`에서 확인합니다. 이 문서는 구조와 사용 방법을 설명하며 실시간 상태 수치를 보관하지 않습니다.

## 설정과 저장

- 운영 설정: `configs/operations.json`
- 원본 모델: `Desktop/모델/champion.pt`
- 고정 Expert 패키지: `Desktop/모델/expert-packages`
- 계좌·경험·시세·프로세스 상태: `runtime/finrlx`
- 정책·optimizer 버전: `runtime/finrlx/policies`
- React / Tailwind CSS / Vite: `frontend`
- 운영 API·Expert 서비스·TorchRL 학습: `src/stockrl/platform`

`runtime`, `.venv`, `node_modules`, 키움 로컬 설정과 가중치는 Git에서 제외합니다. 다른 PC에서 이어서 운영하려면 정상 정지 후 `모델` 폴더 전체와 `runtime/finrlx`를 함께 옮깁니다. `champion.pt`만 복사하면 고정 가중치가 빠집니다.

## 개발 확인

```powershell
$env:PYTHONPATH="src"
$env:PYTHONUTF8="1"
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
cd frontend
npm run typecheck
npm test
npm run build
```

브라우저 테스트는 실행 중인 8766 서버와 설치된 Microsoft Edge를 사용합니다. 빌드 결과 `frontend/dist`를 Python 서버가 직접 제공하며 `no-store`로 응답합니다.

상세 구조는 [운영 architecture](docs/architecture.md), 설치는 [Windows 설치](docs/windows-install.md), 저장 위치는 [저장 안내](docs/project-storage.md)를 참고하세요.

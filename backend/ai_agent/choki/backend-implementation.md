# 헤르메스 백엔드

용도: 공식 전체 실행 기능과 기존 플랫폼 대화·조직 기능을 연결합니다.

- `manager.py`가 chat·models·sessions·mcp·skills·artifacts·native 소메뉴를 취합하고 AI 에이전트 등록 → 전체 메뉴 → 단일 /api로 연결합니다.
- `engine/upstream/`는 공식 전체 Git 트리입니다. 원본 대시보드를 별도 서버에서 대신 실행하거나 공식 도구를 모의 API로 바꾸지 않습니다.
- `engine/launch.py`는 공식 PM의 Python·환경을 선택합니다. `engine/worker.py`는 기존 JSON IPC·대화·조직 연결, `engine/official.py`는 같은 worker 안의 공식 ASGI 수명 주기와 HTTP/WebSocket 전송을 담당합니다.
- `native/asgi.py`의 `/api/ai_agent/choki/native/`는 담당 매니저가 등록한 같은 API 호스트의 공식 프로토콜 통로입니다. PUT·PATCH·DELETE·파일·리다이렉트·스트리밍을 JSON으로 축소하지 않습니다. 인증은 플랫폼 소유자 통로와 worker 내부 공식 토큰을 사용합니다.
- 기존 플랫폼 명령은 `/api`의 operation/payload 계약을 유지합니다. 실제 설정·인증·모델 실행은 공식 구현을 사용합니다.
- 저장은 기존 `runtime/ai_agent/choki/`이며 주 대화·총괄·직원 도구 이력은 기존 SessionDB를 보존합니다. 사업 초안·승인·회의의 기존 업무 기록도 삭제하지 않습니다.

모델·제공자·추론 설정의 기준은 공식 config.yaml입니다. 플랫폼 JSON은 조직 개별 프롬프트·화면·기존 확장 설정을 보존합니다. 제공자를 custom/Codex 두 종류로 제한하던 실행 분기는 공식 resolve_runtime_provider로 교체했습니다. 수동 llama-server 실행과 선별 패키지 설치도 공식 모델 관리자·PM으로 교체했습니다.

초기 준비만 `engine/setup.py`를 사용합니다. 실제 설치된 환경에서는 재설치하지 않습니다. 필요한 외부 계정·서비스 권한은 공식 화면에서 연결하며, 연결 전 외부 실행 성공을 보고하지 않습니다.

2026-10-26 현재 확인: 공식 전체 소스·319개 HTTP 경로 등록, 기존 주 대화 14개 조회, PM Python 3.14.9·SQLite 3.53.1, 실제 공식 게이트웨이 실행, 기존 9B 등록·활성화와 기존 총괄 세션의 실제 직원 위임·파일 읽기·결과 반환을 확인했습니다. 이 위임은 약 6분이 걸렸으며 속도 개선 완료로 기록하지 않습니다. 모든 외부 계정·채널·유료 서비스 실행을 확인한 것은 아닙니다. 실제 모델·스킬·업무 보드 화면, WebSocket 연결 승인, 공통 글꼴·배경 및 가로 넘침 없음, 화면 오류 0건을 확인했습니다. 새 보드 사건을 생성하지 않아 사건 수신은 미확인입니다. 재시작 예약 중 내부 상태 확인을 차단하던 오류를 수정하고 실제 서버 적용을 확인했습니다.

## 공식 기능 연결 대조 (2026-10-26)

공식 `hermes_cli.web_server.app` 전체를 같은 worker에서 사용하며 HTTP 등록 319개 경로를 축소하지 않습니다. 공식 내장 19개 화면 경로와 명령 실행, 설치된 플러그인 화면을 연결합니다. 파일 수와 실제 실행 성공을 혼동하지 않습니다.

| 기능 | 연결 기준 | 실제 확인 범위 |
| --- | --- | --- |
| 모델·제공자·추론·프로필 | 원본 설정·인증·모델 관리자 | 기존 9B 선택·공식 모델 화면, 프로필 화면 조회 |
| 대화·파일·기억·스킬·검색·도구·위임 | 원본 SessionDB·AIAgent·공식 CLI 도구 설정 | 기존 대화 보존, 공식 도구 17종 해석, 작업 환경 API 200 |
| 예약·작업판·메신저·외부 알림·플러그인 | 원본 게이트웨이·각 원본 API와 화면 | 관리 화면 조회, 실제 게이트웨이 홈 일치, 작업판 실시간 연결 |
| 공식 명령·실행 스트림·보조 패널 | 원본 ChatPage·Windows PTY·같은 게이트웨이 RPC·이벤트 | 실제 PTY 출력·RPC 응답·이벤트 수신, 보조 패널 오류 해소 |
| 조직·총괄·회의·승인·기록 | 기존 플랫폼 기능 유지 | 기존 화면 탭 보존, 이전 실제 9B 위임 기록 유지 |

실행·설치 경로의 누락을 수정했습니다. 작업 환경이 제거된 드라이버 경로를 참조해 실패하던 오류도 공식 PM 드라이버·Chromium 탐지로 교체했습니다. 외부 계정 로그인·발송·배포·유료 API·설정 업데이트의 모든 실제 행동을 수행한 것은 아닙니다. 필요한 인증이 없는 기능을 성공 처리하거나 모의 응답으로 대체하지 않습니다. 9B 응답 속도 개선은 이번 범위에서 제외했습니다.

## 설정 저장·서버 재시작 보강 (2026-10-26)

`worker.save_settings`는 입력 전체를 검증한 뒤 공식 설정과 플랫폼 설정을 기록합니다. 저장·결과 조회 오류 시 이전 파일로 복원합니다. 서버 시작 훅이 공식 앱·게이트웨이를 준비하므로 첫 화면 요청에 초기화를 의존하지 않습니다. `models/codex.py`는 요청 당시 모델·제공자 설정을 공식 frozen_runtime_config에 전달해 열린 대화의 연결 정보가 다른 모델과 섞이지 않게 합니다.

실제 확인: 기존 서버 재적용 후 화면 요청 전에 Hermes 실행 프로세스 기동, 잘못된 작업 폴더와 도구 변경을 함께 저장한 요청의 HTTP 400 및 두 설정 파일 원본 유지. 관련 기존 검사 88개 중 실행 68개 통과·조건부 건너뜀 20개. GitHub CI·외부 서비스 실행은 별도 확인 대상입니다.

## canonical owner 연결 상태

실제 공개 `/api/ai_agent/choki/native/api/ws`를 원본 owner에 연결했습니다. 기존 독립 ASGI의 레거시 TUI sidecar에는 없던 session.mutate와 runtime.describe를 실제 확인했습니다. 구형 source=platform인 기존 대화 37개는 일관된 DB 복구본을 남기고 원본 cli source로 연결했으며 ID·메시지 전체 해시는 유지했습니다. 기존 일반 대화의 실제 응답과 owner 조회·내보내기·viewer 연결 해제를 확인했습니다. 상세 경계와 미완료 사항은 engine/README.md와 ../frontend/chat/README.md를 따릅니다. 플랫폼 대화 실행 자체와 owner의 일원화·원본 클라이언트 기능 전체 검증은 아직 미완료입니다.
